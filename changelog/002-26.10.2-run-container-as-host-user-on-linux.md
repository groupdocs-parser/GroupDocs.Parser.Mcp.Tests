# 26.10.2 — run the container as the host user on Linux

## What changed

- **`McpServerFixture`** adds `--user <uid>:<gid>` (read with `id -u` / `id -g`) to `docker run` when
  the tests run on Linux.
- Version pins moved to **26.10.2**: `Directory.Build.props` (was 26.7.3), the `integration.yml`
  `package_version` default and fallback (were 26.5.0), and the image tags in `how-to/` and the
  README (were 26.4.4 / 26.5.0).

## Why

The docker job (`ubuntu-latest · docker`) has failed since it was added: `extract_images` on
`images.pdf` and `images.xlsx` returned
`Access to the path '/data/images_image1.jpeg' is denied. | inner(0): System.IO.IOException: Permission denied`.
The image runs as uid 1654; on a Linux host the bind-mounted temp folder keeps the runner's ownership,
so the container user cannot write the extracted images. The fixture now launches the container the way
the README tells Linux users to, so the suite tests the documented configuration. Server side:
GroupDocs.Parser.Mcp 26.10.2 appends the fix to this error.

The run's other two failures (`ExtractBarcodes_BarcodesPdf_FindsAtLeastOneBarcode`,
`ExtractTables_InvoicePdf_JsonFormatReturnsValidJson`) were a server bug, not a test bug: the unlicensed
`[Evaluation mode]` prefix's bracket was read as the start of the JSON array. Fixed in the server's
26.10.2; no test change was needed.

## Migration impact

None. Windows and macOS runs are unchanged.
